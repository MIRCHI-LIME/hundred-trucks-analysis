MirchiLime Connect · Change record

SIM lead,
toll confirm.

Trucks are now tracked from two independent sources. The driver's SIM reports where the truck has got to; a FASTag toll crossing later confirms it actually went there. The maps draw the two differently, so you can always tell a live guess from a confirmed fact.

The rule

How to read any map in the system

A solid line is the route confirmed by toll crossings — the truck demonstrably passed those plazas. A dotted line is the driver's SIM leading ahead of that confirmation. Where a toll later confirms a stretch the SIM already covered, the solid line simply paints over the dotted one, which is exactly right: confirmation replaces the guess.

For the single current position marker, the fresher of the two readings wins. That is the real gain here — a toll fix can be six hours and 200 km stale, while a SIM fix is at most an hour old. When the SIM is the fresher source, the label says via driver SIM so nobody mistakes it for a confirmed crossing.

New moving parts

Tables · endpoints · schedule

Database

Both tables are created automatically on first start. No migration to run.

TableHolds
truck_simsWhich SIM belongs to which truck, with history kept when a driver changes. One active SIM per truck is enforced by the database itself.
sim_pingsEvery location reading, with its accuracy radius and whether it came from Telenity or the mock.

Endpoints

RoutePurpose
/api/set-simAssign a driver's number to a truck, and take one reading immediately.
/api/remove-simStop tracking that truck's SIM. Ping history is kept.
/api/ping-simsTake readings now — all trucks, or just one.
/api/sim-latestNewest reading per truck, for the fleet overview.

Schedule

ping_sims runs hourly at half past, from 6 am to 11 pm IST — deliberately offset from the FASTag ping on the hour so the two jobs never stack. Change the cadence with SIM_PING_HOURS; 6-22/2 makes it two-hourly.

Putting it live

Deploys to Render on push

  1. Push the code

    The repository is avneetkaurg-ai/hundred-trucks-analysis and Render builds from it automatically. Nothing in this change alters the build or the start command.

  2. Leave Telenity unset for now

    With no credentials configured the system runs on mock locations, so the feature is fully demonstrable the moment it deploys. Nothing else needs configuring.

  3. Assign a driver number

    Open a truck in the dashboard and use ＋ Add driver SIM. It takes one reading straight away, so the truck's position updates immediately.

  4. Share the tracking link

    Use the existing share control on the truck. It mints a link of the form …/track.html?token=… — the token stands in for the vehicle number, so the registration never appears in a URL you send out. That link is the live, shareable page: dual lines, current position, and the driver contact buttons.

A newly added SIM shows no trail for about an hour

A line needs two readings. Until the next hourly poll you get the position marker but no dotted trail — correct behaviour, though it can look like nothing happened. Worth deciding whether onboarding should take a few readings up front.

When Telenity credentials arrive

One function, two settings

Everything routes through a single function, _fetch_telenity() in sim_location.py. It is written against the shape these APIs normally take — send a number, receive a position and an accuracy radius — and marked with a note to confirm against the real documentation. Rewrite that one function, set the two values below, and every map switches from mock to live with no other change. 

TELENITY_URL   the endpoint
TELENITY_KEY   the credential

Every mock reading is tagged as such in the database, so at go-live the demonstration data can be cleared out in a single step without touching anything real.

Still to decide

Not blocking, but worth a decision

  • Driver consent. Indian telecom rules require a subscriber to opt in before their location can be looked up. There is a field ready for this on each SIM record, but nothing enforces it yet. This needs settling before real Telenity calls.
  • The driver's number is public. As agreed, tracking links show Call and WhatsApp buttons with the real number, so anyone holding a link can see it. One setting reverses this if it ever becomes a concern.
  • Manual entry is temporary. Numbers are typed in for now. Once Zoho carries the driver's number, one switch turns the manual control off and the existing sync can fill it in instead — the database already distinguishes the two sources.
  • Accuracy is recorded but not drawn. Every reading stores how precise it was. Showing that as a circle on the map is a later addition needing no rework.
